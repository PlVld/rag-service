# MCP Инструменты

## 1. `search_documents_tool`

**Семантический поиск документов**

| Параметр | Обязательный | Тип | По умолчанию | Описание |
|----------|-------------|-----|--------------|----------|
| `query_text` | ✅ | string | — | Текст запроса |
| `collection_name` | ❌ | string | — | Коллекция Qdrant |
| `limit` | ❌ | integer | 10 | Количество результатов (1-100) |
| `min_score` | ❌ | number | 0.55 | Минимальный score результата (0–1); меньшие отбрасываются; `null` — тоже 0.55, `0` — без ограничения |
| `exact_phrases` | ❌ | string[] | — | До 10 ключевых слов/фраз для точного (лексического) поиска |
| `phrase_mode` | ❌ | string | any | `any` — достаточно любой фразы, `all` — должны встретиться все |
| `filter` | ❌ | object | — | Фильтр по payload |
| `include_old_versions` | ❌ | boolean | false | Старые версии |
| `max_text_length` | ❌ | integer | 0 | Максимальная длина текста в результате (0 = без ограничений) |
| `group` | ❌ | boolean | true | Группировать результаты по category_path |

**Описание параметра `max_text_length`:**
- Если `0` (по умолчанию), текст возвращается в полном объеме
- Если положительное число, текст будет обрезан до указанной длины
- При обрезании добавляется суффикс `...`

**Описание параметра `group`:**
- Если `true` (по умолчанию), результаты группируются по category_path (один результат на категорию)
- Если `false`, возвращаются отдельные чанки (один результат на чанк)

**Описание параметра `min_score`:**
- Порог косинусного сходства (0–1), по умолчанию **0.55**. Результаты с меньшим score не возвращаются
- Передайте `0`, чтобы отключить порог для конкретного запроса; `null` использует значение по умолчанию
- Значение по умолчанию задаётся переменной окружения `SEARCH_MIN_SCORE`
- Отсечение выполняется в Qdrant (`score_threshold`) и повторно после reranking
- При слишком высоком пороге ответ может быть пустым

**Описание параметра `exact_phrases`:**
- Необязательный список ключевых слов и фраз (до 10), по которым выполняется
  дополнительный точный поиск по `raw_text`. Полезен для имён методов, команд,
  идентификаторов, которые семантический поиск может «размыть»
- Слова ищутся целыми токенами без учёта регистра; фраза из нескольких слов —
  как последовательность токенов (пунктуация между словами допускается)
- Точные совпадения добавляются к семантическим, помечаются в выводе
  (`exact_match=true`, `matched_phrases=...`) и идут первыми
- Точные совпадения **не отбрасываются** параметром `min_score`
- Для работы точного поиска на коллекции должен быть создан полнотекстовый
  индекс `raw_text` (см. `scripts/create_text_index.py`); на новых коллекциях
  индекс создаётся автоматически при инициализации

**Описание параметра `phrase_mode`:**
- `any` (по умолчанию) — достаточно совпадения любой из фраз
- `all` — чанк должен содержать все указанные фразы

**Пример:** `{"query_text": "настройка векторного поиска", "collection_name": "documents", "limit": 5}`

**Пример с минимальным score:** `{"query_text": "настройка", "collection_name": "documents", "min_score": 0.5}`

**Пример с точным поиском:** `{"query_text": "перенос данных", "exact_phrases": ["TransferChunk", "Checksum"], "phrase_mode": "all"}`

**Пример с ограничением длины текста:** `{"query_text": "настройка", "collection_name": "documents", "max_text_length": 1500}`

**Пример с отключенными группировкой (отдельные чанки):** `{"query_text": "настройка", "collection_name": "documents", "group": false}`

**Формат ответа:**
Для каждого результата выводится `score`, коллекция (`collection_name`), категория
(`category_path`), идентификатор документа (`source_id`), номера чанков,
из которых собран текст, и общее количество чанков в документе:

```
Найдено 2 результатов:

1. [score=0.850] (collection_name=documents, category_path=Документация / API, source_id=6ba7b810-9dad-11d1-80b4-00c04fd430c8, чанки 2–4 из 10) Текст документа...

2. [score=0.750] (collection_name=documents, category_path=Документация / Настройка, source_id=0f14d0ab-9605-4a62-a9e4-5ed26688389b, чанк 1 из 8) Фрагмент чанка...
```

- При `group=true` указывается диапазон чанков, из которых собран фрагмент: `чанки 2–4 из 10`.
- При `group=false` указывается номер чанка: `чанк 1 из 8`.
- При точном совпадении добавляются `exact_match=true` и
  `matched_phrases=<фразы, вошедшие в текст>`:
  `(collection_name=documents, category_path=..., exact_match=true, matched_phrases=TransferChunk, чанк 1 из 8)`.
  Для группы достаточно точного совпадения хотя бы одного из её чанков.


**Изображения в найденном тексте:**
- Текст чанка — это Markdown, в нём могут быть ссылки на картинки из исходного документа:
  `![Image](/media/<source_id>/<hash>/images/image_000000_ab12cd34.png)`
- Картинки раздаёт сам RAG-сервис по HTTP, токен для их загрузки не требуется
- Ссылка вида `/media/...` — путь относительно корня сервиса, перед ним нужно подставить
  базовый адрес (`http://localhost:8000` + `/media/...`)
- Чтобы сервис сразу отдавал абсолютные ссылки, задайте `MEDIA_BASE_URL` в `.env`

## 2. `search_categories_tool`

**Поиск категорий по запросу (результаты всегда сгруппированы по коллекциям)**

| Параметр | Обязательный | Тип | По умолчанию | Описание |
|----------|-------------|-----|--------------|----------|
| `query_text` | ✅ | string | — | Текст запроса |
| `limit` | ❌ | integer | 10 | Количество категорий (1-50) |
| `min_score` | ❌ | number | 0.55 | Минимальный score категории (0–1); меньшие отбрасываются; `null` — тоже 0.55, `0` — без ограничения |
| `exact_phrases` | ❌ | string[] | — | До 10 слов/фраз для точного поиска по пути категории |
| `phrase_mode` | ❌ | string | any | `any` — достаточно любой фразы, `all` — должны встретиться все |

**Особенности:**
- Всегда возвращает результаты, сгруппированные по коллекциям
- Для каждой коллекции показывает категории с релевантными путями и их семантическим score
- Коллекции без релевантных категорий не включаются в результат
- `exact_phrases` ищет слова в пути категории (без учёта регистра). Точные
  совпадения идут первыми, помечаются `[exact]` и не отбрасываются `min_score`.
  Поиск выполняется по расширенному пулу семантических кандидатов
  (`limit × 5`, не более 200)

**Пример ответа:**
```
Релевантные категории по коллекциям:

### Коллекция: syntx_1C
- 1С / Общие объекты / DOM / ДокументDOM (score: 0.538)
- 1С / Общие объекты / Web-сервисы / WSПараметр / Свойства / Документация (score: 0.523)

### Коллекция: 1c_integration
- Интеграция / API / Методы / СоздатьЗапрос (score: 0.485) [exact]
```

**Пример вызова:** `{"query_text": "документация API", "limit": 10}`

**Пример с точным поиском:** `{"query_text": "методы", "exact_phrases": ["API"]}`

## 3. `get_category_hierarchy_tool`

| Параметр | Обязательный | Тип | По умолчанию | Описание |
|----------|-------------|-----|--------------|----------|
| `collection_name` | ❌ | string | — | Коллекция Qdrant. Если не указано, возвращает категории для всех коллекций. |
| `depth` | ❌ | integer | 1 | Количество уровней для получения (0 - только список коллекций без категорий, 1-10 - иерархия категорий). |
| `categories` | ❌ | object | — | Массив полных путей категорий. Если указаны, возвращает только коллекции с этими категориями. |
| `limit` | ❌ | integer | 5000 | Максимальное суммарное количество категорий в ответе. `null` — без ограничения. |

**Описание параметра `depth`:**
- Если `0`, возвращается только список коллекций без категорий
- Если `1-10`, возвращается иерархия категорий на указанное количество уровней
- Максимальное значение: 10

**Описание параметра `categories`:**
- Если указаны, возвращаются только коллекции, содержащие эти категории
- Путь категории может быть строкой вида "Категория / Подкатегория"

**Описание параметра `limit`:**
- Ограничивает суммарное количество категорий во всём ответе
- Коллекции обходятся по порядку, пока не исчерпан лимит
- При обрезке в конце вывода появляется строка `Показано N из M категорий (limit=...)`
- `null` отключает ограничение (осторожно: вывод может быть очень большим)

**Пример (все коллекции, глубина 1):** `{"depth": 1}`

**Пример (конкретная коллекция, глубина 2):** `{"collection_name": "documents", "depth": 2}`

**Пример (с фильтром по категориям):** `{"depth": 2, "categories": ["Документация / API", "Документация / руководства"]}`

**Пример ответа:**
```
Иерархия категорий:

### Коллекция: syntx_1C
- Документация / API (27273 чанков)

### Коллекция: 1c_integration
- Интеграция / API (931 чанков)
```

## 4. `get_grouped_text_tool`

**Сгруппированный текст чанков без семантического поиска**

| Параметр | Обязательный | Тип | По умолчанию | Описание |
|----------|-------------|-----|--------------|----------|
| `collection_name` | ❌ | string | — | Коллекция Qdrant. Если не указано, выборка по всем коллекциям, кроме служебной коллекции категорий. |
| `categories` | ❌ | string[] | — | Пути категорий. Учитывается точное совпадение и вложенность (`A / B` включает `A / B / C`). |
| `documents` | ❌ | string[] | — | Идентификаторы документов (`source_id`). |
| `include_old_versions` | ❌ | boolean | false | Включать старые версии документов. |
| `max_text_length` | ❌ | integer | 0 | Максимальная длина текста каждой группы (0 = без ограничений). |
| `limit` | ❌ | integer | 20 | Максимальное количество групп «документ + категория» (1–1000). |

**Особенности:**
- Не требует `query_text` и не использует эмбеддинги — выборка детерминированная.
- Чанки группируются по паре «документ + категория» и склеиваются в порядке `chunk_index`.
- Для каждой группы выводятся `source_id`, коллекция, категория, номера чанков и общее количество чанков в документе.
- Фильтры `categories` и `documents` применяются на стороне Qdrant; `raw_text`
  читается только для групп, попавших в ответ после `limit`.
- Без `categories` и `documents` выполняется полный перебор коллекции. Для больших
  коллекций это медленнее, поэтому фильтры рекомендуется указывать.

**Пример вызова:** `{"collection_name": "documents", "categories": ["Документация / API"], "limit": 10}`

**Пример ответа:**
```
Найдено 1 групп:

1. (source_id=6ba7b810-9dad-11d1-80b4-00c04fd430c8, collection_name=documents, category_path=Документация / API, чанки 0–2 из 5) Текст первого чанка
Текст второго чанка
Текст третьего чанка
```

## Методы JSON-RPC 2.0

| Метод | Описание |
|-------|----------|
| `initialize` | Инициализация клиента |
| `ping` | Проверка доступности |
| `tools/list` | Список инструментов |
| `tools/call` | Вызов инструмента |

## Аутентификация
- **URL:** `http://localhost:8000/mcp`
- **Method:** POST
- **Auth:** Bearer `<RAG_SERVICE_API_KEY>` (см. `app/mcp/middlewares.py`)
- **Content-Type:** application/json
